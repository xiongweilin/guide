# 资格

[English](./qualification.md) | [简体中文](./qualification.zh-CN.md)

> 灵感来源：人治与法治的冲突。

资格回答：**什么条件足以让一个候选或状态进入下一步？**

它不是一个通用分数，而是状态转换所需依据的结构。资格只是 guide 六个同等基础分析维度之一；它不高于区分、价值、能力、变化或他者，也不定义这些维度的内容。

## 最小状态

`未满足 → 累积中 → 足够 → 进入`

这里的 `未满足` 是资格状态，不是认识论上的否定。它可能表示条件已知为假、证据缺失、状态未知，或者所需依据尚未建立；这些原因本身仍应保持可区分。

“累积”不一定是数值增加，“足够”也不要求统一阈值。实际条件可能是：

- 必要条件逐步满足；
- 证据和反例逐步被区分；
- 依赖变得有效；
- authority、approval 或 commitment 建立；
- verification 完成；
- 风险、成本和剩余未知在当前目的下可接受。

因此 qualification 的核心不是“分数多高”，而是：

> 在当前对象、范围、目的、时间尺度和条件下，什么使这个转换现在可以成立？

## 两种资格机制

现实并不总是以同一种方式提供“足够”。至少要区分两种机制。

### 解释型资格

**解释型资格**用于“什么算足够”无法在事前被完全规定清楚的情况。参与者需要解释对象、语境、证据、反证、目的、竞争 framing 和剩余未知，再形成一个可追责的判断：当前依据是否已经足够。

开放问题、诊断、战略、设计、例外处理、新颖案例，以及相关变量或权重无法事先完整枚举的判断，通常都包含解释型资格。

解释型资格不等于任意判断。至少应保留：

- 正在判断的对象和转换；
- 范围、目的和时间尺度；
- 证据和反证；
- 假设与默认区分；
- 会实质影响结果的竞争解释或候选；
- 剩余未知和被接受的风险；
- 暂定闭合的理由；
- 谁对这个判断负责；
- review 和 reopening 条件。

因此：

`判断有理由 ≠ 判据已经在事前完全规定`

`解释所得的足够 ≠ 普遍真理`

### 规定型资格

**规定型资格**用于相关条件已经明确到足以检查的情况：规则、谓词、阈值、状态机 guard、协议、测试、contract、approval set 或等价 specification 已经规定当前转换什么算足够。

例如年龄阈值、必须签署的角色集合、schema 约束、测试套件、policy predicate 或带版本的 authorization condition。

规定型资格至少应保留：

- 规则或 contract 的 identity 与 version；
- 规则的 authority 或来源；
- 适用范围和有效时间；
- 所需 inputs 及其版本；
- predicates、thresholds 或必要条件；
- evaluator 与 evaluation result；
- exception、override 和 reopening 条件。

规则写得清楚，只会让“按规则检查”更确定；它并不会自动证明这条规则本身对当前对象适用、仍然有效、具有 authority，或者值得继续维持。

因此：

`规则明确 ≠ 规则已经取得当前适用资格`

`predicate 为真 ≠ transition 自动获得授权`

### 张力、组合与转换

两种机制解决的问题不同，因此形成持续张力：

- 规定型资格提高确定性、可重复性和可自动化程度，但只能在已经编码进去的区分和条件内部工作；
- 解释型资格能够处理含糊、新颖和未完全规定的现实，但需要可追责判断，并保留更多分歧和修订空间。

现实活动经常是**混合资格**。混合资格不是第三种原始机制，而是解释型与规定型 qualification slice 的显式组合：一个 transition 既可能需要规定型 gate，也需要解释型 closure；或者先通过解释判断“这条规定是否适用”，再执行规定型检查。

两者还会随时间转换：

`反复解释 → 显式规则化 → 规定型资格`

`新颖案例 / 规则含糊 / 依据变化 → reopening → 解释型资格`

但转换必须显式发生。过去的一次解释不能静默变成确定性规则；一个确定规则被满足，也不能消除“该规则现在是否仍适用”的解释问题。

## Qualification slice

每一个具体 qualification slice 至少需要知道：

- 原始资格机制：解释型和/或规定型，是否由两者组合，以及为什么；
- 当前对象或状态；
- 想进入的下一状态；
- 范围、目的和时间尺度；
- 必须满足和必须保持的条件；
- 当前仍开放的自由度；
- 支持依据；
- 谁拥有定义或标准制定权，谁提出，谁评估或判断，谁决定或授权，谁验证，以及谁能够重新打开；
- 失效、退出、review 和 revalidation 条件。

不同领域有不同资格条件，因此不存在一个全局 `qualified = true` 可以替代所有语义。

即使最终状态都叫 `sufficient`，也不能抹掉它是通过哪一种资格机制产生的。相同结果、不同机制的两条记录，不具有相同语义。

## 资格收缩

资格不只发生在最终“进入”或 closure 的那一刻。很多中间操作都会减少当前仍然开放的自由度，例如：

- 排除候选；
- 停止搜索；
- 固定解释；
- 冻结接口或验证标准；
- 缩小 scope；
- 限制行动；
- 把临时安排变成承诺。

这些都可以视为**资格收缩（qualification contraction）**。

`开放空间 → 有资格的收缩 → 收敛 → 暂定闭合`

每一次收缩都需要与其排除或冻结范围相称的依据。“尚未生成”“当前不可见”或“当前资源下没有找到”，不能静默升级成“不可能”。某个约束或验证标准一旦在当前 slice 获得资格，也不能只因为当前实现无法满足，就为了适配结果而改写。

因此 closure 不是资格第一次出现的位置，而是连续的、有资格的收缩达到当前用途要求后的特殊位置。

## 定义权、判断权与决定权

资格处在一个更大的权力结构中。至少应区分三种权力：

1. **定义权**：规定或修改问题边界、候选空间、分类、可接受证据、判准、阈值、验证标准和完成条件的权力。
2. **判断权**：解释当前依据，并判断已经定义的条件是否满足、是否足够的权力。资格最直接发生在这个位置。
3. **决定权**：决定一个判断是否进一步形成承诺、授权、资源配置、规则采用、现实行动、继续、暂停或终止的权力。

至少保持：

`定义权 ≠ 判断权 ≠ 决定权`

`标准制定权 ≠ evaluator 权力 ≠ 行动 / 承诺权`

拥有其中一种权力，不自动取得另外两种。能够定义标准，不等于能够宣布自己已经满足标准；能够判断依据足够，不等于因此取得配置资源或改变现实的 authority；拥有决定权，也不等于能够在看到结果之后重新定义证据或降低标准。

这种分离不要求任何低风险事务都必须由三个不同的人或机构完成。在影响小、容易恢复的活动中，同一参与者可以合理承担多个位置。但随着影响范围、不可逆性、依赖程度或权力不对称增加，应通过独立证据、独立评价、受限的规则修改权、外部否决或停止路径、复核、申诉或其他与领域相称的机制，使这种分离变成真实约束。

需要防止的核心失败是自我验证闭环：

`定义规则 → 按规则判断 → 决定后果 → 规则不方便时再改规则`

即使每个局部步骤在程序上都很整齐，只要同一位置同时控制“什么算候选”“什么算足够”以及“这个判断是否变成现实约束”，整个资格过程仍可能被俘获。

因此，资格本身不产生定义权或决定权。资格只回答：在一个已经给定但仍可被审查的转换结构中，当前依据是否足够。周围权力的正当性、分配和边界仍是独立问题，可能需要价值、他者、领域治理、法律、制度程序或其他外部结构来回答。

## 责任归属与资格正交

责任回答：**谁**负责定义、提出、判断、授权、执行、验证、停止、修复、记录或重新打开？

资格回答：当前转换的**依据是否已经足够**？

至少保持：

`存在负责角色 ≠ 资格条件已经满足`

`资格条件已经满足 ≠ 自动获得 authority`

一个角色可以拥有判断责任，但不能因此制造证据或前置条件；反过来，依据已经足够，也不表示相应 authority 自动属于当前主体。

## 不可合法短路

non-substitution 可以写成一个更一般的规则。

如果从 `X` 到 `Y` 之间还存在一个必须承担的责任、依据或资格位置 `R`：

`X → R → Y`

就不能静默压缩成：

`X → Y`

当关键责任尚未承担时，合法处理大体只有四类：

1. **新增缺失责任位置**：当前结构确实漏掉了一个不可替代的区分；
2. **明确转交**：该责任属于其他领域、authority、程序或理论 owner；
3. **保持开放**：继续取得依据、候选或证据，而不伪造闭合；
4. **停止继续规定**：当前没有资格形成更强结论。

这条规则不保证最终结论一定正确；它防止一个较容易的答案占据本来属于更困难问题的语义位置，而中间责任实际上从未完成。

## 组合资格

资格不会自动满足组合律。

`qualified(C1) + qualified(C2) + ... ≠ qualified(C1 ∘ C2 ∘ ...)`

分别获得资格的组件、断言、规则、行动或子系统，在组合后仍可能因为 assumptions、scope、时间、资源、权限、接口、副作用或 failure dependency 的相互作用而失效。

至少要分开三个问题：

- 每个局部组件在自身 slice 中是否有资格；
- 这些局部资格组合时是否彼此兼容；
- 局部表示是否包含足够信息，使联合结构本身获得资格。

因此：

`局部有资格 ≠ 联合兼容 ≠ 组合整体有资格`

只要组合会产生新的约束、副作用、反馈、authority 扩张、依赖或 failure propagation，就需要组合层自己的 qualification basis。

## 转交完整性

即使两个模块内部都没有偷换，责任也可能在 handoff 中丢失。

重要转交应保留足够上下文，使接收方知道“实际转交了什么”以及“没有声称什么”。视领域而定，至少包括：

- 当前结论或状态；
- object、scope、purpose 和 time scale；
- 支持依据与 source provenance；
- 关键假设；
- 主要剩余未知；
- 仍有资格继续考虑的替代候选；
- 反证、证伪或失效条件；
- 当前 closure 状态；
- review、revalidation 和 reopening trigger。

`完成 handoff ≠ 下游自动重新取得资格`

接收方只能在转交实际保留的 qualification 范围内依赖这些材料。转交本身不会静默创造新的 authority、更大的 scope、更强的证据力度或永久有效性。

## 资格不能静默继承

最重要的规则是：

`上一层成立 ≠ 下一层自动成立`

例如：

`默认区分 ≠ 世界结构`

`能够提出问题 ≠ 问题已经成立`

`问题成立 ≠ 答案可靠`

`证据存在 ≠ 判断足够`

`判断足够 ≠ 目标值得承诺`

`目标值得承诺 ≠ 有权决定`

`有权决定 ≠ 当前有执行权限`

`执行请求成功 ≠ 现实效果已经发生`

`现实效果发生 ≠ 目标已经完成`

`目标完成 ≠ 长期仍然有效`

很多严重错误不是某一步完全错误，而是一个 slice 的资格被静默提升成了另一个 slice 的资格。

## Closure 与 reopening

有限活动不可能永久保持所有可能性开放。常见循环是：

`开放 → 收敛 → 暂定闭合 → 继续活动 → 条件变化时重新打开`

Closure 只表示当前目的下已经足够继续，不表示永久真理。

当事实、范围、依赖、authority、价值、成本、风险或环境发生实质变化时，应触发 review、revalidation 或 reopening。

Reopening 只恢复候选和选择空间，它不会自动产生新答案、新决定或新 authority。

## 有限闭合与元资格

资格判断本身也是一个判断，因此可能需要 review；但本框架不要求在任何行动之前建立无限层级的“资格的资格”。

每个 qualification slice 只做局部闭合：它绑定的对象、范围、目的、时间尺度、支持依据、authority、剩余未知和重新打开条件，必须对当前正在判断的转换已经足够。如果这些依据本身的有效性后来成为另一个转换的实质条件，再把它显式提升为 review 或 revalidation 的对象。

因此：

`暂定的局部闭合 ≠ 绝对基础`

`资格可以被复核 ≠ 每个资格都需要无限向前追溯的资格`

## 状态与转换

一个结果状态可能合理，但到达它的路径仍然无效。

所以资格既检查：

- 当前状态是否可接受；
- 也检查从旧状态到新状态的转换依据是否有效。

合法终点不能反向证明路径合法。

## 跨领域迁移强度

当同一种结构在不同领域出现时，至少区分三种迁移强度：

1. **共同问题**：只能迁移提问方式或 framing。
2. **形式相似**：可以迁移表示、比较或计算结构。
3. **机制相似**：只有对象、边界条件和机制本身也足够接近时，才可以有限迁移预测或干预经验。

`形式相似 ≠ 机制证据`

一个结构在领域 A 获得了机制层支持，不表示它在领域 B 自动取得同样资格。跨领域复用本身也需要独立 qualification，不能只靠术语或形式相似完成。

## 与其他维度的边界

资格建立在[区分](./distinction.zh-CN.md)之上，但不能由区分自动推出；它约束[价值](./value.zh-CN.md)、[能力](./capability.zh-CN.md)、[变化](./change.zh-CN.md)和[他者](./others.zh-CN.md)中的状态转换，却不能替代这些维度自身的内容。
