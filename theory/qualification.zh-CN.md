# 资格

[英文](./qualification.md) | [简体中文](./qualification.zh-CN.md)

> 灵感来源：人治与法治的冲突。

资格回答：**什么条件足以让一个候选或状态进入下一步？**

它不是一个通用分数，而是状态转换所需依据的结构。资格只是 guide 六个同等基础分析维度之一；它不高于区分、价值、能力、变化或他者，也不定义这些维度的内容。

## 最小状态

`未满足 → 累积中 → 足够 → 进入`

这里的 `未满足` 是资格状态，不是认识论上的否定。它可能表示条件已知为假、证据缺失、状态未知，或者所需依据尚未建立；这些原因本身仍应保持可区分。

“累积”不一定是数值增加，“足够”也不要求统一阈值。实际条件可能是：

- 必要条件逐步满足；
- 证据和反例逐步被区分；
- 依赖变得有效；
- 权限、批准或 承诺建立；
- 验证完成；
- 风险、成本和剩余未知在当前目的下可接受。

因此资格的核心不是“分数多高”，而是：

> 在当前对象、范围、目的、时间尺度和条件下，什么使这个转换现在可以成立？

## 两种资格机制

现实并不总是以同一种方式提供“足够”。至少要区分两种机制。

### 解释型资格

**解释型资格**用于“什么算足够”无法在事前被完全规定清楚的情况。参与者需要解释对象、语境、证据、反证、目的、竞争框定和剩余未知，再形成一个可追责的判断：当前依据是否已经足够。

开放问题、诊断、战略、设计、例外处理、新颖案例，以及相关变量或权重无法事先完整枚举的判断，通常都包含解释型资格。

解释型资格不等于任意判断。至少应保留：

- 正在判断的对象和转换；
- 范围、目的和时间尺度；
- 证据和反证；
- 假设与默认区分；
- 会实质影响结果的竞争解释或候选；
- 剩余未知和被接受的风险；
- 暂定闭合的理由；
- 谁对这个判断负责；
- 复核和 重新打开条件。

因此：

`判断有理由 ≠ 判据已经在事前完全规定`

`解释所得的足够 ≠ 普遍真理`

### 规定型资格

**规定型资格**用于相关条件已经明确到足以检查的情况：规则、谓词、阈值、状态机守卫条件、协议、测试、契约、批准集合或等价规范已经规定当前转换什么算足够。

例如年龄阈值、必须签署的角色集合、模式约束、测试套件、策略规则谓词或带版本的授权条件。

规定型资格至少应保留：

- 规则或契约的 身份与 版本；
- 规则的权限或来源；
- 适用范围和有效时间；
- 所需输入及其版本；
- 谓词、阈值或必要条件；
- 评估者与 评估结果；
- 例外、优先覆盖和 重新打开条件。

规则写得清楚，只会让“按规则检查”更确定；它并不会自动证明这条规则本身对当前对象适用、仍然有效、具有权限，或者值得继续维持。

因此：

`规则明确 ≠ 规则已经取得当前适用资格`

`谓词为真 ≠ 状态转换自动获得授权`

### 张力、组合与转换

两种机制解决的问题不同，因此形成持续张力：

- 规定型资格提高确定性、可重复性和可自动化程度，但只能在已经编码进去的区分和条件内部工作；
- 解释型资格能够处理含糊、新颖和未完全规定的现实，但需要可追责判断，并保留更多分歧和修订空间。

现实活动经常是**混合资格**。混合资格不是第三种原始机制，而是解释型与规定型资格切片的显式组合：一个状态转换既可能需要规定型门槛，也需要解释型闭合；或者先通过解释判断“这条规定是否适用”，再执行规定型检查。

两者还会随时间转换：

`反复解释 → 显式规则化 → 规定型资格`

`新颖案例 / 规则含糊 / 依据变化 → 重新打开 → 解释型资格`

但转换必须显式发生。过去的一次解释不能静默变成确定性规则；一个确定规则被满足，也不能消除“该规则现在是否仍适用”的解释问题。

## 资格切片

一个具体资格切片只需要保留足以回答以下问题的上下文：

- 使用哪种资格机制，正在判断什么转换；
- 范围、目的、时间尺度、条件和支持依据；
- 什么仍然开放，什么正在被排除或冻结；
- 谁定义标准、判断、决定或授权、验证，以及谁能重新打开；
- 什么条件会使结论失效、进入复核或重新验证。

不同领域的资格条件不同，因此一个全局 `已取得资格 = true` 不能保存全部语义。即使结果都叫“足够”，也不能抹掉产生它的机制和依据。

## 资格收缩

资格可以发生在最终进入之前，但前提是某次中间收缩本身正在主张“已有充分依据可以排除或冻结可能性”。例如排除候选、停止搜索、冻结标准，或者把临时安排变成承诺。

只有在确实主张“依据已经足够”时，这种收缩才是**资格收缩**：

`减少选项 ≠ 默认就是资格问题`

`开放空间 → 有资格的收缩 → 暂定闭合`

有资格的收缩需要与其排除或冻结的范围相称的依据。“尚未生成”“当前不可见”或“当前资源下没有找到”，不能静默升级成“不可能”。连续的资格收缩可以形成闭合，但并非所有自由度减少都属于资格。

## 定义权、判断权与决定权

资格处在一个更大的权力结构中。至少应区分三种权力：

1. **定义权**：规定或修改问题边界、候选空间、分类、可接受证据、判准、阈值、验证标准和完成条件的权力。
2. **判断权**：解释当前依据，并判断已经定义的条件是否满足、是否足够的权力。资格最直接发生在这个位置。
3. **决定权**：决定一个判断是否进一步形成承诺、授权、资源配置、规则采用、现实行动、继续、暂停或终止的权力。

至少保持：

`定义权 ≠ 判断权 ≠ 决定权`

`标准制定权 ≠ 评估者权力 ≠ 行动 / 承诺权`

拥有其中一种权力，不自动取得另外两种。能够定义标准，不等于能够宣布自己已经满足标准；能够判断依据足够，不等于因此取得配置资源或改变现实的权限；拥有决定权，也不等于能够在看到结果之后重新定义证据或降低标准。

这种分离不要求任何低风险事务都必须由三个不同的人或机构完成。在影响小、容易恢复的活动中，同一参与者可以合理承担多个位置。但随着影响范围、不可逆性、依赖程度或权力不对称增加，应通过独立证据、独立评价、受限的规则修改权、外部否决或停止路径、复核、申诉或其他与领域相称的机制，使这种分离变成真实约束。

需要防止的核心失败是自我验证闭环：

`定义规则 → 按规则判断 → 决定后果 → 规则不方便时再改规则`

即使每个局部步骤在程序上都很整齐，只要同一位置同时控制“什么算候选”“什么算足够”以及“这个判断是否变成现实约束”，整个资格过程仍可能被俘获。

因此，资格本身不产生定义权或决定权。资格只回答：在一个已经给定但仍可被审查的转换结构中，当前依据是否足够。周围权力的正当性、分配和边界仍是独立问题，可能需要价值、他者、领域治理、法律、制度程序或其他外部结构来回答。

## 责任归属与资格正交

责任回答：**谁**负责定义、提出、判断、授权、执行、验证、停止、修复、记录或重新打开？

资格回答：当前转换的**依据是否已经足够**？

至少保持：

`存在负责角色 ≠ 资格条件已经满足`

`资格条件已经满足 ≠ 自动获得权限`

一个角色可以拥有判断责任，但不能因此制造证据或前置条件；反过来，依据已经足够，也不表示相应权限自动属于当前主体。

## 不可合法短路

如果从 `X` 到 `Y` 实质依赖一个中间责任、依据或资格位置 `R`，就不能把它静默省略：

`X → R → Y`，而不是 `X → Y`。

如果 `R` 缺失，只在确有必要时补上该位置；否则应转交给拥有该责任的领域或程序、保持问题开放继续取得依据，或者停止形成更强主张。这个规则防止语义替代，但不保证最终结论一定正确。

## 组合资格

资格不会自动满足组合律：

`已取得资格(C1) + 已取得资格(C2) + ... ≠ 已取得资格(C1 ∘ C2 ∘ ...)`

局部资格不能自动建立联合兼容性或组合整体的资格。只有当交互引入实质性的新假设、范围、时间、权限、依赖、副作用、反馈或故障传播时，才需要组合层自己的依据。

## 转交完整性

重要转交只需要保留足以防止下游过度主张的上下文：

- 当前结论或状态，以及范围、目的和时间尺度；
- 支持依据、关键假设、剩余未知和重要替代候选；
- 失效、复核、重新验证或重新打开条件；
- 当前闭合和权限的边界。

`完成转交 ≠ 下游自动重新取得资格`

转交不会静默创造更大范围、更强证据、新权限或永久有效性。

## 资格不能静默继承

整个仓库的不可替代规则直接适用于资格：

`一个切片成立 ≠ 下一切片自动成立`

尤其要保持：

`存在证据 ≠ 判断已经足够`

`判断足够 ≠ 目标值得承诺`

`目标值得承诺 ≠ 已取得决定权`

`现实效果发生 ≠ 目标已经完成`

资格只能携带该切片实际建立的范围和依据。

## 有限闭合与重新打开

有限活动需要暂定闭合：

`开放 → 收敛 → 暂定闭合 → 继续活动 → 条件变化时复核 / 重新打开`

闭合只对当前对象、范围、目的、时间尺度和依据局部成立，不表示永久真理或绝对基础。本框架也不要求行动之前先完成无限层级的元资格。

事实、范围、依赖、权限、价值、成本、风险或环境发生实质变化时，可以进入复核、重新验证或重新打开。重新打开只恢复候选和选择空间，不自动产生新答案、新决定或新权限。

`暂定局部闭合 ≠ 绝对基础`

`资格可以被复核 ≠ 每个资格都需要无穷前置资格`

## 状态与转换

一个结果状态可能合理，但到达它的路径仍然无效。

所以资格既检查：

- 当前状态是否可接受；
- 也检查从旧状态到新状态的转换依据是否有效。

合法终点不能反向证明路径合法。

## 跨领域迁移强度

当同一种结构在不同领域出现时，至少区分三种迁移强度：

1. **共同问题**：只能迁移提问方式或框定。
2. **形式相似**：可以迁移表示、比较或计算结构。
3. **机制相似**：只有对象、边界条件和机制本身也足够接近时，才可以有限迁移预测或干预经验。

`形式相似 ≠ 机制证据`

一个结构在领域 A 获得了机制层支持，不表示它在领域 B 自动取得同样资格。跨领域复用本身也需要独立资格，不能只靠术语或形式相似完成。

## 与其他维度的边界

资格使用[区分](./distinction.zh-CN.md)来明确正在判断什么，但不能由区分自动推出；它可以约束[价值](./value.zh-CN.md)、[能力](./capability.zh-CN.md)、[变化](./change.zh-CN.md)和[他者](./others.zh-CN.md)中的状态转换，而不定义这些维度自身的内容。
