# Finite system: the user of the framework

[English](./finite-system.md) | [简体中文](./finite-system.zh-CN.md)

The user of this framework is a **finite system**.

A person, family, team, organization, institution, Agent, or technical system can be analyzed as a finite system. "Finite" is not a defect judgment. It is the condition that no user can observe reality completely at zero cost, exhaust every candidate, perform infinite reasoning, and control every relevant causal condition at once.

## 1. Finitude

A finite system is constrained by at least:

- limited sensing and data sources;
- limited language, classification, and representation;
- limited time, attention, and computation;
- limited resources and tools;
- limited permissions and callable interfaces;
- limited knowledge of other systems' internal states;
- limited knowledge of future and counterfactuals;
- limited control over causal processes;
- limited correction, recovery, and exit speed.

A finite system therefore needs **provisional closure**. Otherwise the fact that reality always contains more unknowns would turn action into infinite exploration.

This is why the sufficiency operator exists: it does not require complete knowledge, only a boundary sufficient for the current purpose and next transition.

## 2. Current boundary

For an activity, a finite system forms a current boundary (B):

```text
B = {distinction, relation, causality, temporality, possibility, value}
```

This does not require six tables or modules. It means important activity must not silently flatten these semantics into a single total state.

The boundary also carries **epistemic status**. Epistemic status is not a seventh dimension; it is metadata about the source and strength of current claims, such as:

- provenance and source;
- observation / inference / assumption / report by others;
- unverified / supported / disputed / refuted / unknown;
- scope and time of applicability;
- key assumptions;
- review and invalidation conditions.

`currently believes X != X is established as reality-side fact`

`high model confidence != authoritative fact`

## 3. Possible, reachable, controllable, and callable

A finite system must distinguish:

- **possible**: a state remains in the current possibility space;
- **reachable**: a feasible path exists from current conditions;
- **controllable**: the system can exert enough control over relevant causal variables;
- **callable**: the required tools, interfaces, resources, collaborators, authority, and recovery paths are currently accessible.

Therefore:

`Possible(X) != Reachable(X) != Controllable(X) != Callable(X)`

These differences cut across possibility, causality, relation, temporality, and system interfaces; they do not require a separate "capability" dimension.

When no path has yet been found, the appropriate state may be `unknown`, not `cannot`. "Cannot" requires an explicitly bounded scope and sufficient grounds.

## 4. Self, assistance, and leverage

Callable paths may be formed through:

- **self**: the system's own body, knowledge, skill, and directly controlled resources;
- **assistance**: tools, devices, AI, professional services, institutional interfaces, or others;
- **leverage**: environments, rules, networks, incentives, automation, or existing trends where the system does not perform the main causal process itself.

Much modern capability is distributed across relations, infrastructure, institutions, and tools rather than located only inside the actor.

Therefore:

`has a skill != currently has a callable path`

`causal effect exists != intervention interface exists`

`intervention interface exists != current authority to use it`

## 5. Self-model and calibration

A finite system maintains a working model of its resources, tools, interfaces, permissions, collaborators, failure modes, and reachable paths. That model can be stale.

`believes it can do X != X is currently reachable`

`could do X in the past != can still do X now`

Changes in providers, tools, permissions, resources, collaborators, environments, recovery conditions, or institutions require recalibration.

New distinctions may reveal paths that were previously unseen; new tools, relations, and interfaces may even create paths that did not previously exist.

## 6. Responsibility and authority

A finite system can occupy multiple roles, but must distinguish:

- defining problems, candidates, or rules;
- judging sufficiency;
- deciding;
- authorizing;
- executing;
- observing;
- verifying;
- recovering;
- reopening.

One role does not automatically create another role's authority.

`can judge != authorized to decide`

`authorized to decide != automatically authorized on underlying resources`

`can execute != worth executing`

Responsibility should also be proportionate to the knowledge, authority, capability, and causal contribution actually available at the time.

## 7. Maneuverability

Strong capability is not only the ability to execute the current plan. It also includes the ability to:

- generate alternatives;
- switch tools and dependencies;
- stop effects;
- recover control;
- bear transition costs;
- rebuild preconditions and authority;
- explain what happened;
- preserve dissent, evidence, and the ability to distinguish again.

The deepest lock-in is not merely losing one option, but losing the ability to rediscover alternatives and recover control.

A finite system therefore asks not only "can I do this now?" but also "after doing it, can I still revise myself?"
