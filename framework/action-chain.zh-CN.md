# 行动链：从当前边界到现实反馈

[English](./action-chain.md) | [简体中文](./action-chain.zh-CN.md)

行动链是本框架的**循环结构**。六维描述当前边界，充分性决定探索还是决策；行动链则把决定连接到现实，并让现实反馈重新进入下一轮。

## 1. 最小循环

```text
当前活动 / 当前目的
    ↓
六维当前边界
    ↓
充分性判断
    ├─ 不足 → 探索 → 修订边界 ─┐
    └─ 足够 → 决策              │
                ↓               │
              行动链             │
                ↓               │
               现实              │
                ↓               │
            现实侧反馈            │
                ↓               │
        保持 / 修订 / 重新打开 ───┘
```

这不是严格的单向流水线。决策可能暴露缺失区分并回到探索；执行中可能发现权限失效；观察可能表明因果假设错误；价值或关系变化也可能使原决定不再充分。

## 2. 行动链内部

对有现实后果的活动，至少保持：

```text
决定
→ 承诺 / 治理依据
→ 授权
→ 执行尝试
→ 现实效果
→ 观察
→ 验证
→ 结果
→ 完成 / 剩余义务
→ 保持、恢复、修订或重新打开
```

这些位置不是每次都要成为独立数据库对象，但语义不能被抹掉。

至少保持：

`候选 ≠ 决定`

`决定 ≠ 授权`

`授权 ≠ 执行`

`执行器报告成功 ≠ 现实效果已经发生`

`现实效果发生 ≠ 预期后置条件已验证`

`后置条件已验证 ≠ 全部目标 / 义务完成`

`事项完成 ≠ 长期责任已经解除`

## 3. 决定与承诺

决定在当前可接受空间中形成选择。它可能关闭替代项、配置资源、建立他者预期、触发权限申请或形成长期路径依赖。

实质决定最好绑定：

- 当前边界 / 版本；
- 候选与重要排除项；
- 重要理由与冲突；
- 接受的未知；
- 决定主体与决定权来源；
- 时间尺度；
- 形成的承诺；
- 预期效果；
- 复核、反转和重开条件。

好的结果不能倒推当时决策过程一定有效；坏结果也不能自动证明当时决定不合理。

## 4. 授权与执行

技术能力不会创造权限，决定也不会自动创造底层资源权限。

授权至少要绑定：

- 谁；
- 对什么资源或对象；
- 做什么操作；
- 在什么范围；
- 基于什么权限来源；
- 何时签发、何时到期或被撤销。

执行前还需要检查当前状态、版本、前置条件、授权、关键依赖和允许副作用。

合法终点不能证明到达它的路径合法。

## 5. 外部效果与部分成功

数据库事务只能保证本地边界，不能让外部世界与本地状态共同原子提交。

因此行动链必须能够表示：

- 已执行但效果未知；
- 外部已发生但本地未确认；
- 部分成功；
- 重复请求但外部效果不能安全重放；
- 需要补偿；
- 需要校正；
- 需要恢复；
- 需要重新授权。

`传输幂等 ≠ 效果幂等`

超时或确认丢失不能默认变成“失败并安全重试”。当外部效果含糊时，应进入校正。

## 6. 观察与验证

观察负责从现实侧取得状态，而不是复述执行器自己的输出。

观察至少应保留来源、对象身份、来源版本、观察时间、可用性和时效状态。

验证检查被冻结的后置条件，例如：

- 对象是否正确；
- 目标状态是否发生；
- 范围是否符合；
- 不应改变的状态是否保持；
- 是否出现重要副作用。

执行器自己的成功回执不能代替独立现实回读。

## 7. 效果溯源

如果系统声称“这个行动产生了这个结果”，应能够追踪：

```text
当前边界
→ 充分性依据
→ 决定
→ 授权
→ 执行
→ 现实效果
→ 观察
→ 验证
→ 结果
```

终点状态正确不足以证明因果链正确；并发行动、人工操作、重复执行或其他参与者也可能产生相同终点。

## 8. 义务与完成

业务要求完成什么，不应由执行规划器自己定义。否则规划器漏掉步骤时，可能制造内部一致的假成功。

因此需要把**义务**和**计划**分开。

`计划执行完 ≠ 义务全部满足`

完成判断应检查必需状态、必需操作、权限条件、验证结果和剩余义务。长期责任还可能要求转交、接续者、补偿、持续观察或明确解除。

## 9. 反馈与重开

现实反馈可能触发不同强度的响应：

1. 更新当前表示中的值；
2. 重新验证旧事实、规则、权限或依赖；
3. 修订某个六维结构；
4. 重新打开候选空间或问题框定；
5. 重新进入探索；
6. 重新形成决定；
7. 停止、补偿或恢复；
8. 缩界、替换或废弃当前框架。

历史记录不应因为重新打开而被删除。撤销、补偿、回滚和新决定应形成新的可追踪记录。

`重新打开 ≠ 自动反转`

`历史决定现在失效 ≠ 历史决定从未存在`

## 10. 速度、可逆性与锁定

行动链的纠错速度必须与现实变化和损伤形成速度相称。

可比较：

`发现 + 判断 + 停止 + 恢复 + 再授权`

与

`错误传播 + 损伤累积 + 锁定`

存在纠错机制，不表示纠错足够快。

可逆性也至少分成：

- **状态可逆**：现实状态能否恢复；
- **控制可逆**：有限系统能否重新取得停止、修改、接管、迁移或退出能力；
- **认识可逆**：证据、知识、记录、异议通道和验证能力是否仍然存在。

行动链的目标不是让一切可逆，而是在形成不可逆承诺时让原因、权限、风险和恢复边界保持显式。
