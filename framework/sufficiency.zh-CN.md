# 充分性算子

[English](./sufficiency.md) | [简体中文](./sufficiency.zh-CN.md)

充分性是本框架的**算子**，不是第七维。

它回答：

> 对当前目的和下一次转换，当前边界是否已经足够？

可以抽象为：

`S(B, P, T) → {不足, 实质不确定, 足够}`

其中：

- (B)：当前六维边界及其认识状态；
- (P)：当前目的；
- (T)：准备进入的下一次转换，例如继续探索、排除候选、形成决定、授权、执行、验证或完成。

充分性不是现实本身的属性，而是当前边界、目的和转换之间的关系。

## 1. 最小状态

`未满足 → 累积中 → 足够 → 进入`

“未满足”可能表示条件已知为假、证据缺失、状态未知、所需依据尚未建立，或者适用规则本身仍有争议。这些原因不能压成一个布尔值。

“累积”也不要求数值增加。依据可以包括：

- 必要条件逐步满足；
- 证据与反证逐步形成；
- 依赖有效；
- 权限、批准或承诺建立；
- 验证完成；
- 风险、成本与剩余未知对当前目的可接受。

## 2. 两种基本机制

### 解释型充分性

当“什么算足够”无法事前完整规定时，有限系统需要基于语境、证据、反证、竞争解释、目的与剩余未知形成可追责判断。

开放问题、诊断、战略、设计、例外处理和新颖案例通常包含解释型充分性。

至少保留：

- 判断对象和转换；
- 范围、目的、时间尺度；
- 证据和反证；
- 假设与默认区分；
- 会实质改变结果的竞争解释；
- 剩余未知与接受风险；
- 暂定闭合理由；
- 判断责任；
- 复核和重开条件。

`判断有理由 ≠ 判据已经事前完全规定`

`解释得到的足够 ≠ 普遍真理`

### 规定型充分性

当相关条件已经明确到可以检查时，使用显式规则、谓词、阈值、状态机守卫、协议、测试、契约或批准集合。

至少保留：

- 规则 / 契约身份和版本；
- 权限或来源；
- 适用范围与有效时间；
- 输入及版本；
- 谓词、阈值或必要条件；
- 评估者与结果；
- 例外、覆盖和重开条件。

`规则明确 ≠ 规则已经适用于当前对象`

`谓词为真 ≠ 转换自动获得授权`

### 组合与转换

现实活动可以组合两种机制，例如先解释“这条规则是否适用”，再执行规定型检查。

`反复解释 → 显式规则制定 → 规定型检查`

`新颖案例 / 规则含糊 / 依据变化 → 重开 → 解释型判断`

过去解释不能静默变成确定规则；规则满足也不能取消对其适用性、时效和权限的检查。

## 3. 充分性切片

一个具体充分性判断只需要携带与当前转换相称的上下文：

- 正在判断什么转换；
- 当前边界版本；
- 目的、范围、时间尺度；
- 支持依据；
- 仍开放的未知；
- 被排除或冻结的候选；
- 判断者、规则制定者、决定者与授权者；
- 失效、复核、重开条件。

不同转换的“足够”不是同一个全局布尔值。

`足够回答问题 ≠ 足够授权行动`

`足够执行 ≠ 足够确认效果`

`足够确认效果 ≠ 足够宣布全部目标完成`

## 4. 有充分依据的收缩

当系统排除候选、停止搜索、冻结标准或把临时安排变成承诺时，它正在缩小可能性空间。

只有在确实主张“已有充分依据排除或冻结”时，这才是充分性收缩：

`开放空间 → 有充分依据的收缩 → 暂定闭合`

`减少选项 ≠ 自动已经充分`

“没有生成”“当前不可见”“当前资源下没找到”都不能静默升级成“不可能”。

## 5. 定义权、判断权与决定权

至少分开：

1. **定义权**：定义问题边界、候选空间、证据、判准、阈值、验证标准与完成条件；
2. **判断权**：判断当前依据是否满足或已经足够；
3. **决定权**：决定该判断是否转化成承诺、资源配置、规则采用、行动、继续、暂停或终止。

`定义权 ≠ 判断权 ≠ 决定权`

同一参与者可以在低风险情境承担多个位置，但影响范围、不可逆性、依赖或权力不对称越高，越需要独立证据、受限规则修改权、复核、申诉、否决或停止路径。

需要防止的典型闭环是：

`定义规则 → 自己判断满足 → 自己决定后果 → 不方便时再修改规则`

充分性本身不会产生权限。

## 6. 责任与充分性正交

责任回答“谁负责”；充分性回答“依据是否足够”。

`存在负责角色 ≠ 当前依据足够`

`当前依据足够 ≠ 自动获得权限`

责任角色不能制造不存在的证据、条件或权限。

## 7. 不可合法短路

如果从 (X) 到 (Y) 实质依赖一个中间责任或依据位置 (R)，就不能静默省略：

`X → R → Y`，而不是`X → Y`。

缺失位置应被显式补足、转交、保持开放或停止，而不是用相邻状态替代。

## 8. 组合不自动成立

`S(C1) + S(C2) + ... ≠ S(C1 ∘ C2 ∘ ...)`

局部组件分别充分，不自动建立组合后的兼容性。只有当组合引入新的范围、假设、权限、依赖、副作用、反馈或故障传播时，才需要组合层自己的充分性依据。

## 9. 转交完整性

重要转交应保留足以防止下游过度主张的上下文：

- 当前结论与范围；
- 目的和时间尺度；
- 支持依据；
- 关键假设；
- 剩余未知；
- 重要替代候选；
- 失效、复核和重开条件；
- 权限边界。

`完成转交 ≠ 下游自动取得更强充分性`

转交不会创造更大范围、更强证据、新权限或永久有效性。

## 10. 暂定闭合与重新打开

有限系统需要：

`开放 → 收敛 → 暂定闭合 → 行动 → 现实反馈 → 保持 / 重开`

闭合只对当前对象、范围、目的、时间尺度和依据局部成立，不是永久真理。

事实、范围、关系、因果假设、依赖、权限、价值、成本、风险或环境发生实质变化时，应重新评估充分性。

`暂定闭合 ≠ 绝对基础`

`可以复核 ≠ 需要无限元复核`

## 11. 状态与转换

一个结果状态可以合理，但到达它的路径仍然无效。

因此充分性既可以检查目标状态，也可以检查状态转换本身。

`合法终点 ≠ 合法路径`

## 12. 跨领域迁移

跨领域复用至少区分：

- 共同问题；
- 形式相似；
- 机制相似。

`形式相似 ≠ 机制充分`

领域 A 的成功不会自动建立领域 B 的充分性。迁移本身也需要相称依据。
