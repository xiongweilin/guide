> 明确我们区分了什么、什么足以成立、什么值得、什么能做、结构如何变化，以及人与人如何相互影响。

这是一个关于**人类活动基础结构及其工程表达**的思想与方法索引。

个人、家庭、团队、组织、制度、Agent 和技术系统都可以成为分析对象；Agent 只是“能够参与当前活动的主体”的一种形式化表达，不是这套框架成立的前提。

## 世界边界

本仓库把**世界**保留为认知边界。

当前观察、语言、模型、分类、schema、ontology 或知识图谱都不能因为可用，就被默认视为世界本身的完整结构。文档讨论的是**可区分世界中的人类活动**，不是世界本身的终极本体论。

至少保持：

- **世界（认知边界）**：当前表示之外仍然存在什么，保持开放；
- **可区分世界 / 可区分范围**：在当前感知、语言、工具、交互、能力和接口下原则上能够形成的区分；
- **已区分范围**：当前已经获得、形成并能调用的区分；
- **默认区分**：语言、文化、接口、制度、历史决定或既有模型静默带入的分类和边界。

因此：

`当前表示 ≠ 世界本身`

`未进入当前表示 ≠ 不存在 ≠ 不可能`

## 人类活动的六个基础维度

对同一项活动，至少同时保留六个不能静默替代的分析维度。它们不要求彼此独立、正交，也不要求处在同一逻辑层级：

| 维度 | 最小结构 | 核心问题 |
| --- | --- | --- |
| [**区分**](./theory/distinction.zh-CN.md) | `世界边界 → 可区分世界 / 范围 → 已区分范围` | 什么能够成为可区分内容，什么已经被区分，什么仍在当前表示之外？ |
| [**资格**](./theory/qualification.zh-CN.md) | `解释型 / 规定型` + `未满足 → 累积中 → 足够 → 进入` | 什么条件足以成立，以及这个“足够”是在解释中形成，还是按明确规则检查？ |
| [**价值**](./theory/value.zh-CN.md) | `外界规范 ↔ 内在规范` | 什么值得、应当、被要求或被拒绝？ |
| [**能力**](./theory/capability.zh-CN.md) | `未知 / 不能 / 能够` + `自身 / 辅助 / 借势` | 哪些结果当前能够实现、依据是什么，以及借助什么实现？ |
| [**变化**](./theory/change.zh-CN.md) | `稳定 / 过渡 / 无稳定结构` | 当前面对的是持续结构、转换过程，还是尚无稳定结构？ |
| [**他者**](./theory/others.zh-CN.md) | `关联强度 × 一致 / 冲突` | 谁与谁相互影响，并在哪些维度一致或冲突？ |

六维不是六类对象，也不是六条彼此独立的轴，而是同一活动中不能静默互相替代的分析维度。它们可以相互约束，并形成反馈关系。

六个维度在本框架中**同等基础**。任何一个维度都不是总维度，也不能取得对另外五个维度内容的定义权。区分问什么能够进入表示；资格问什么依据足以支持一次转换；价值问什么值得追求或拒绝；能力问什么当前能够实现以及借助什么实现；变化问什么能够保持、正在转换或需要重开；他者问多个参与者之间的关系、权力、承认、一致与冲突怎样改变活动。任何一个维度都可以约束、挑战或要求重新打开其他维度。

资格仍然是这六维之中的状态转换语义，而不是整个框架的高阶 owner。现实中至少存在两种形成张力的基本机制：**解释型资格**通过对语境和证据的可追责判断形成“足够”，**规定型资格**则按照已经明确的规则、谓词、阈值或 contract 检查“足够”。同一活动可以同时包含两者，但不能静默互相替代。区分与能力构成一类重要反馈：当前能力、工具、接口和他者限制什么能够进入可区分范围，而新形成的区分又可能揭示或创造新的可达路径；其他维度之间也可以形成自己的反馈关系。因此下面的阅读顺序只用于导航，不表示本体论推导、重要性排序或单向因果层级。

例如：

`能做到 ≠ 值得做到`

`值得做到 ≠ 已获得行动资格`

`当前稳定 ≠ 长期有效`

`我的区分 / 价值 / authority ≠ 他人的区分 / 价值 / recognition`

## 六维之间的 non-substitution

贯穿整个仓库的共同规则是：**一层成立不能静默替代另一层成立。**

典型边界包括：

`默认区分 ≠ 世界结构`

`能够提出问题 ≠ 问题已经成立`

`问题成立 ≠ 答案可靠`

`解释型资格 ≠ 规定型资格`

`规定规则已满足 ≠ 规则对当前对象适用 / 仍有效 / 有权约束`

`判断足够 ≠ 目标值得承诺`

`值得做 ≠ 有能力做`

`有能力做 ≠ 有权做`

`已授权 ≠ 已执行`

`执行成功 ≠ 现实效果已发生`

`现实效果发生 ≠ 目标已完成`

`历史有效 ≠ 当前仍有效`

这些边界在理论层由六维解释，在工程层由精确语义和 AIOS 继续保存。

## 框架完整性与自我挑战

本框架不把“完整”定义成“所有终极问题都已经有答案”。

更有用的标准是：

`未知没有被伪装成已知`

`缺失责任没有被静默替代`

`遇到边界时知道如何转交、重开或停止`

因此，能力实现仍然不完备，并不妨碍框架对“当前主张到哪里为止”保持相称责任。

框架自身也不免于这些规则。**guide 是一个可修订的工作框架，不是关于世界的真理来源。** 它的分类、区分、资格规则、价值 framing、能力模型、变化模型和对他者的表示都可能出错。现实侧 observation、反例、预测失败、行动失败、意外后果或更好的 framing，都可以给人足够理由去缩界、修订、替换，或者停止使用某个主张或框架。

### 不证明维度数量

guide 永远不尝试证明为什么恰好是六个维度；如果未来维度数量发生变化，也不因此产生新的证明义务。

当前维度数量只是一种**工作性闭合**：只要它能够帮助区分现实问题、防止重要语义替代、支持有效行动和工程表达，并且能够接受现实失败的修正，就足以用于当前目的。

因此：

`当前六维有用 ≠ 现实存在恰好六个基本维度`

`维度数量变化 ≠ 必须先证明旧数量错误`

`框架对当前用途足够好 ≠ 框架已经获得终极基础`

框架不无限递归追问“为什么一定是这个数量”。如果继续追问已经不能产生实质上更好的区分、决定、预测、行动或校正，就可以暂时闭合；未来现实反馈仍然可以重新打开它。

### 不做形式化证明，以现实使用指标评价

guide 永远不尝试通过形式化证明来建立框架自身的有效性。为了提高表达精度或工程可实现性，可以使用精确定义、符号简写、状态机、invariant、测试或具体领域的 formal verification；但这些都不能证明 guide 就是世界的真实结构或终极结构。

guide 主要通过六个现实使用指标接受评价：

| 指标 | 使用问题 |
| --- | --- |
| **正确性** | 区分、判断、行动和最终主张，是否与当前可取得的现实侧证据、预期语义和实际结果相符？ |
| **可用性** | 人和系统是否能够以不过度困难的方式理解、应用、维护和修订这套框架？ |
| **可靠性** | 在重复使用、条件变化、异常和失败下，框架是否仍能稳定提供可依赖的指导，并支持校正或恢复？ |
| **性能** | 使用框架形成决定、协调或工程结果时，其延迟、响应速度和吞吐是否满足当前任务需要？ |
| **容量 / 可扩展性** | 当用户、数据、任务、领域、依赖和互动复杂度增长时，框架是否仍然可用，而不会出现不可接受的退化？ |
| **效率** | 为取得有用结果所消耗的时间、计算、金钱、注意力、协调、维护和机会成本是否相称？ |

这六个指标只是**使用指导**，不是六个新的理论维度、原理或证明义务。guide 同样不证明为什么这些指标恰好是六个。具体使用时，哪些指标相关、怎样测量、什么阈值足够、各自权重多大，都由具体处境决定。

因此：

`形式精确 ≠ 对框架完成形式化证明`

`局部 formal verification ≠ guide 已被证明为真`

`单一指标表现良好 ≠ 整体已经充分`

`当前相关指标足够好 ≠ 永久有效`

当当前用途下相关指标已经足够好时，可以暂时闭合，不继续追求基础性证明；当现实侧结果恶化时，由使用它的人重新打开框架。

### 退役不是理论能够自行执行的规则

理论不是行动主体。它不能保证人会遵守它自己写下的 review、替换或退役规则。

同一个理论，对一个人仍然有用，对另一个人可能已经过时，对第三个人可能只保留一部分；不同的人、组织和情境也不会在同一时间停止使用它。理论退役不需要同步，也不可能被理论自身强制同步。

因此 guide 不定义“满足 X 条件后理论必须自行退役”这类实际上无法执行的规则。它最多只能给出一些可能足以支持 review、缩界、替换、归档或停止使用的信号。是否真的发生这些行为，属于活着的参与者及其处境、价值、能力和关系。

因此：

`理论写下退役条件 ≠ 理论能够执行退役`

`一个使用者停止使用 ≠ 所有使用者应同时停止`

`仍有人继续使用 ≠ 理论在所有情境中仍然充分`

所以修订和退役是**人围绕框架进行的实践**，不是框架自身的自主行为。

一个竞争 framing 或理论，不需要先翻译成当前六维词汇，才有资格暴露当前框架的盲区或失效；只有在整合、federation 或 migration 时，才需要处理双方语义映射。内部自洽不能替代现实反馈。

当重要现实问题反复无法被现有维度定位或转交；当“保持开放 / unknown”长期不再产生新区分、新候选、有效缩界或有理由的停止；或者维持体系需要不断增加特殊例外却没有相称收益时，人就有理由重新打开核心结构。这些只是 review signal，不是框架能够自行执行的命令。

一个实际可用的维护循环是：

`使用 → 遭遇现实 / 反例 → 积累失败 → 人在依据足够时修订、缩界、替换、归档或停止使用`

而不是持续扩大核心，不是无限证明当前维度数量，也不假定所有使用者会同步更新或退役框架。
