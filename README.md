# guide

这组文档讨论一个共同问题：**有限的人和 AI 如何形成判断、取得授权、改变现实，并在长期系统中保持纠错和改变方向的能力。**

目标不是建立新的总理论，而是把容易混淆、又会直接影响现实结果的边界整理清楚，并尽量使用成熟领域已有的语言。

## 怎么读

普通读者可以按这个顺序开始：

1. [现实、约束与变化](./现实、约束与变化.md)：为什么稳定、变化、规则和重新评估都需要条件。
2. [认识与判断](./认识与判断.md)：如何在信息有限时形成暂时可靠的判断，而不过度断言。
3. [互动、价值与制度](./互动、价值与制度.md)：多主体、权力、承认、正当性和价值冲突为什么不能压成一个目标。
4. [行动、授权与可靠性](./行动、授权与可靠性.md)：为什么“知道怎么做”不等于“有权做”，执行成功也不等于现实目标完成。

工程师可以优先阅读：

- [精确语义](./精确语义.md)：把 source of truth、authorization、state transition、provenance、verification、reconciliation、revalidation 等边界落实为工程 contract。
- [行动、授权与可靠性](./行动、授权与可靠性.md)：处理真实副作用、失败传播、恢复、接管和长期权限。

如果想了解这些观点为什么被这样组织、哪些旧术语被删除，以及它们与成熟研究和工程传统的关系，可以最后阅读 [编写历史](./编写历史.md)。

## 边界

这些文档用于设计、审查和沟通，不是 runtime authority。AI 或软件系统不应因为读取这些文本就获得新的权限、事实或执行资格。

真正进入产品的内容，应落成明确的 policy、schema、state machine、authorization check、verification contract 和 conformance test。
